0 · AI, ML & DL basics

One problem, four approaches: "Is this email spam?"

1 · RULE-BASED AI

Hand-written rules

if "free money" in text:
  return "spam"

✅ Transparent
❌ Spammers change one word and it breaks

2 · MACHINE LEARNING

Learn from labelled examples

You pick features: link count, CAPS ratio, sender age. A model learns the weights from 100k labelled emails.

✅ Adapts to data
❌ Humans must design features

3 · DEEP LEARNING

Learns features itself

A neural network reads the raw text. It learns that "w1n a pr1ze" and "claim your reward" mean the same thing.

✅ Catches paraphrases
❌ Needs lots of data + compute

4 · GENERATIVE AI

Prompt an LLM

"Is this phishing? Explain why, then draft a safe reply to the sender."

✅ No training, explains, also writes
❌ Slower, costlier, less predictable

Trend: more flexibility each step, but also more compute, cost and unpredictability. Pick the simplest tool that works.
0 · AI, ML & DL basics

Machine learning: learning from data

SUPERVISED

Labelled examples

Input → known answer. The model learns the mapping.

Ex: email → spam/not spam
Ex: house features → price
Ex: customer history → churn

UNSUPERVISED

No labels

Find structure on its own: groups, outliers, topics.

Ex: customer segments
Ex: fraud anomaly detection
Ex: topic discovery in reviews

REINFORCEMENT

Reward signal

An agent tries actions, gets rewards or penalties, improves its strategy.

Ex: AlphaGo, game bots
Ex: robot walking
Ex: RLHF to align chatbots

SELF-SUPERVISED

Labels from the data

Hide part of the data, predict it. Labels come free.

Ex: predict the next word → how LLMs are pre-trained
Ex: fill in masked words (BERT)

Key idea: self-supervised learning is why LLMs could scale: the internet is a giant free labelled dataset.

One bank, four learning styles

SUPERVISED

Fraud detection

Millions of past transactions labelled "fraud" or "fine". The model learns which patterns predict fraud.

UNSUPERVISED

Customer segments

No labels. The model groups customers by behaviour: savers, spenders, small businesses.

REINFORCEMENT

Reminder timing

An agent tries different send times for payment reminders; reward = payment made on time.

SELF-SUPERVISED

Document LLM

Reads huge text collections, hiding words and predicting them. No human labelling needed.

Connection to GenAI: the last one is how every LLM starts life. The other three are the classic ML toolbox.

from sklearn.ensemble import RandomForestClassifier
from sklearn.model_selection import train_test_split

X = df[["num_links", "caps_ratio", "sender_age_days"]]   # features (inputs)
y = df["is_spam"]                                          # labels (answers)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.2)

model = RandomForestClassifier().fit(X_tr, y_tr)               # TRAIN: learn the rules
print(model.score(X_te, y_te))                             # EVALUATE on unseen data -> 0.94
model.predict([[7, 0.6, 2]])                                # PREDICT -> [1]  (spam)
Notice: we never wrote a spam rule. We supplied examples and the algorithm found the rules.

0 · AI, ML & DL basics

Learning vs. memorising

UNDERFITTING

Too simple

Misses the real pattern. Bad on training data and new data.

Like studying one chapter for the whole exam.

GOOD FIT

Generalises

Captures the pattern, ignores the noise. Good on unseen data.

Like understanding the concepts.

OVERFITTING

Memorises

Perfect on training data, poor on new data. It learned the noise.

Like memorising last year's answer sheet.

Why we split the data

Train 70% · the model learns here
Validate 15%
tune settings
Test 15%
final exam
LLM link: memorised training text is one reason models can repeat facts wrongly or leak data. Always judge a model on data it hasn't seen.
0 · AI, ML & DL basics

Deep learning: layers of tiny functions

One neuron

out = activation( w1·x1 + w2·x2 + … + b )

Weights w are the learned numbers. Billions of them = "parameters".

How it learns (repeat millions of times)

1Forward pass: make a prediction
2Loss: measure how wrong it was
3Backpropagation: find who is to blame
4Gradient descent: nudge weights to reduce loss

"Deep" = many hidden layers. Early layers learn simple features (edges, letters); later layers learn abstract ones (faces, meaning).

0 · AI, ML & DL basics

Architectures: different shapes for different data

CNN

Images

Slides small filters over pixels to find edges, shapes, objects.

Face unlock, X-ray reading, self-driving vision

RNN / LSTM

Sequences (older)

Reads one step at a time, carrying a memory. Slow and forgets long context.

Early speech + translation. Largely replaced.

TRANSFORMER

Language + more

Attention lets every token look at every other token, in parallel.

GPT, Claude, Gemini, Llama, BERT

DIFFUSION

Image / video generation

Start from noise, remove it step by step toward an image that matches the prompt.

Stable Diffusion, Midjourney, video models

Takeaway: the transformer is the engine behind modern GenAI. It scaled better than anything before it.

Task: "is this email a refund request?" three ways

TRAIN

6 · Inside an LLM

Tokens: how the model sees text

Text is chopped into tokens (word pieces); each maps to an integer ID. Type below.

≈ 1 token ≈ ¾ of an English word. Cost, speed and limits are all measured in tokens. (Simplified tokenizer.)
Example

Estimate the token bill before you build

# 1 page ≈ 500 words ≈ 670 tokens
tokens_per_doc = 500 / 0.75
docs_per_day   = 1000
input_tokens   = tokens_per_doc * docs_per_day
               # ≈ 670,000 / day

cost = input_tokens / 1_000_000 * PRICE_IN
     + output_tokens / 1_000_000 * PRICE_OUT

Steps

  1. Estimate tokens per request
  2. Multiply by volume
  3. Plug in your model's price per million tokens (input and output differ)

Surprises

Output tokens usually cost more than input. Long system prompts and few-shot examples are paid for on every call.

Habit: look up current pricing for your model and always compute a daily estimate before shipping.

6 · Inside an LLM

Embeddings: meaning as coordinates

An embedding turns text into a list of numbers. Similar meaning → nearby points.

The gold star lands among the login messages even though it shares no words with them.

Real embeddings have hundreds to thousands of dimensions; this is a 2D sketch.

Example

Semantic search vs keyword search

USER SEARCHES HELP CENTRE"I can't get into my account"
KEYWORD MATCH

Looks for the words "get", "into", "account".

  • "Account settings overview" ✔ word match, wrong answer
  • "How to reset a forgotten password" ✘ no shared words, missed
EMBEDDING MATCH

Compares meaning.

  • "How to reset a forgotten password" ✔ ranked #1
  • "Two-factor login problems" ✔ ranked #2
Why it matters: this is the retrieval step of RAG, coming in a later session.
6 · Inside an LLM

Attention: every word looks at every other word

Parallel

Reads all tokens at once, so training scales on GPUs.

Contextual

The same word gets a different meaning depending on its neighbours.

Stacked

Dozens of layers, many attention "heads" each. That's the transformer.

Example

Attention resolves ambiguity

SENTENCE A"The trophy didn't fit in the suitcase because it was too big." → it = the trophy
SENTENCE B (one word changed)"The trophy didn't fit in the suitcase because it was too small." → it = the suitcase

A rule-based system would need a hand-written rule for each case. The model learned, from text alone, that "big" attaches to the thing that doesn't fit and "small" to the container.

Prompting link: the model weighs all your words. Contradictory or irrelevant text in a prompt pulls attention in the wrong direction.

8 · Working with LLMs

Context window: the model's working memory

The model sees only what is inside the window on this call. It has no memory between calls.

System prompt
Chat history
Documents / retrieved text
Question
Room for the answer

Everything above must fit in the model's token limit, input and output together.

Bigger ≠ free

More tokens cost more and run slower.

Lost in the middle

Details buried in very long input can be missed. Put key facts at the start or end.

You manage it

Trim, summarise or retrieve; don't paste everything.

Example

Why the chatbot forgot my name

TURN 1 (long ago)User: "I'm Priya, on the Pro plan." … TURN 80User: "Which plan am I on?" Bot: "I don't have that information."
WHAT HAPPENED

The app kept sending the full history until it exceeded the limit, then dropped the oldest turns. Turn 1 fell out of the window.

FIXES
  • Summarise older turns
  • Pin key facts (name, plan) in the system prompt
  • Store facts in a database and retrieve them
Remember: the API is stateless. "Memory" is something your code re-sends on every call.
8 · Working with LLMs

Temperature & top-p: play with it

Prompt: "My favourite programming language is"

Temperature: 1.0 Top-p: 1.00

Greyed bars are excluded by top-p. Slide temperature to 0.1, then 2.0.

Facts, extraction, code → low (0–0.3). Brainstorming, stories → higher (0.7–1.0).
Example

Same prompt, different temperature

Prompt: "Suggest one name for a coffee shop near a train station."

TEMPERATURE ≈ 0
Run 1: Platform Coffee
Run 2: Platform Coffee
Run 3: Platform Coffee

Consistent. Good for classification, extraction, tests.

TEMPERATURE ≈ 1
Run 1: The Last Carriage Café
Run 2: Rail & Roast
Run 3: Brew Line Junction

Varied. Good for brainstorming, bad for anything that must repeat.

Illustrative outputs.

Rule: choose temperature by task. Low when there is one right answer, higher when you want options.
9 · Reality check

A jagged skill profile

Summarising text
Drafting & rewriting
Translation
Writing code
Exact arithmetic
Citing real sources
Today's news (no tools)

Illustrative profile, not a benchmark.

LEAN ON IT FOR

Language-shaped work with a human reviewer.

ADD A TOOL FOR

Maths (calculator), fresh data (search), private data (RAG), actions (APIs).

NEVER TRUST BLINDLY

Facts, citations, legal or medical claims.

Example

Surprising failures

ARITHMETIC"What is 48,372 × 9,614?" Model may answer a plausible-looking number that is slightly wrong. Fix: let it call a calculator tool.
LETTER COUNTING"How many r's in 'strawberry'?" Tokens are chunks, not letters, so counting characters is hard. Fix: ask it to spell the word out first, or use code.
Pattern: if a task is exact, mechanical and checkable, give it to code. Use the LLM for the language around it.
